# Domyland для Home Assistant

Кастомная интеграция для управления **домофонами** (открытие дверей) и просмотра
**камер** жилого комплекса через платформу [Domyland](https://domyland.ru)
(приложение «Домиленд+», провайдер умного дома — UJIN).

Логин выполняется вашим **Яндекс ID** — тем же, что и в приложении. Один аккаунт
покрывает все ваши адреса (квартиры, апартаменты, машиноместа); двери и камеры
каждого дома подтягиваются автоматически.

> Интеграция обращается только к официальному API вашего приложения от вашего
> имени. Используйте её для доступа к своему жилью, к которому у вас есть законный
> доступ.

## Что появляется в Home Assistant

- **Замок** (`lock`) на каждую дверь/калитку/подъезд — действие «Открыть» шлёт
  импульс (`PUT /smarthome/access/{id}/open`). Состояния у API нет, поэтому замок
  всегда показывается «заперто», а любое открытие — импульсное. Тип `lock` удобно
  пробрасывается в Алису: «Алиса, открой калитку».
- **Камеры** (`camera`, MJPEG): общедомовые камеры ЖК (`GET /cameras`) **и**
  встроенная камера каждого домофона/калитки (`GET /smarthome/access/{id}`, поле
  `video`). Живой поток проксируется напрямую (multipart/x-mixed-replace).
  Ссылки обновляются при опросе API каждые 5 минут; при сбое списка используются
  сохранённые источники с проверкой доступности.
- Каждый дом (`buildingId`) — отдельное устройство, под ним его двери и камеры.

### Сенсоры помещения (форк `sna2021/ha-domyland`, ветка `feat/probe-api-sensors`)

Дополнительно к дверям и камерам, опрос раз в 5 минут вместе с ними:

- **Счётчики** (`sensor`): показания каждого умного счётчика квартиры из
  `/smarthome/place/management` — вода (м³, `TOTAL_INCREASING`), тепло (Гкал).
- **Счёт ЖКХ** (`sensor`, ₽): сумма текущего счёта из `/main-payment-widget`.
  Платёжные токены (`paymentContext`/`paymentLink`) в атрибуты не попадают.
- **Заявки УК** (`sensor`): число активных заявок из `/my-orders/dispatcher`,
  в атрибутах статусы, даты, флаги обновлений и непрочитанных сообщений.
- **Гостевые пропуска** (`sensor`): список разовых пропусков из `/v2/pass`.
- **Уведомления ЖКХ** (`sensor`): число непрочитанных из `/notifications`,
  в атрибутах последние 5 (заголовок, превью, дата).

Только чтение API: никаких записей (создание пропусков/заявок не выполняется).
Если сервиса в ЖК нет, сенсор просто остаётся пустым/недоступным — ошибки
отдельных эндпоинтов не влияют на двери и камеры.

Камеры можно отключить в настройках интеграции (их бывает много — у CityBay 38).

## Установка

### Через HACS (рекомендуется)

1. HACS → Integrations → ⋮ → Custom repositories.
2. Добавьте `https://github.com/he110/ha-domyland`, категория **Integration**.
3. Установите «Domyland», перезапустите Home Assistant.

### Вручную

Скопируйте `custom_components/domyland/` в `config/custom_components/` вашего HA и
перезапустите.

## Настройка (получение токена Яндекса)

Приложение «Домиленд+» авторизуется через Яндекс, и API требует Яндекс-OAuth токен
в каждом запросе. Интеграция получает его так же, как это делает
[YandexStation](https://github.com/AlexxIT/YandexStation) — разовым копированием:

1. Настройки → Устройства и службы → **Добавить интеграцию** → «Domyland».
2. Откройте предложенную ссылку и войдите своим **Яндекс ID**.
3. После входа Яндекс перенаправит вас на страницу (браузер может показать ошибку
   открытия приложения — это нормально). **Скопируйте весь URL** из адресной строки
   или токен `y0_...` из него.
4. Вставьте скопированное в поле config flow.

Дальше интеграция сама обменяет Яндекс-токен на JWT Domyland (живёт ~10 лет) и
найдёт все ваши адреса.

### Если токен Яндекса истёк

Home Assistant сам предложит **повторную авторизацию** (reauth) — повторите те же
шаги с получением токена. JWT при этом сохраняется.

### Если пропали домофоны и камеры (восстановление с 0.3.2)

Domyland иногда возвращает `success: true`, но пустые списки устройств, хотя
индивидуальные запросы к ранее известным домофонам продолжают работать.
Удалять и заново добавлять интеграцию в этом случае не нужно.

- **Двери и встроенные камеры** восстанавливаются по ID из реестра HA и локального
  архива интеграции. Дверь, пропавшая из списка, считается доступной только после
  успешного индивидуального запроса; старые данные доступности и видеоссылки
  домофонов не воспроизводятся.
- **Общедомовые камеры** сохраняют последние полученные источники. Если API больше
  не отдаёт камеру, сохранённый поток проверяется получением JPEG-кадра при каждом
  обновлении. Неработающая ссылка не делает камеру доступной.
- Архив переживает перезапуск HA и удаляется вместе с записью интеграции.
  Если дом больше не присутствует в текущем списке помещений аккаунта,
  его устройства не восстанавливаются из архива.

В установках до 0.3.2 архив общедомовых камер ещё не создавался: одного ID камеры
из реестра недостаточно для восстановления ссылки. Если у вас есть личная
резервная копия ответов API, откройте **Настройки интеграции → Резервная копия
камер (JSON)**. Формат: объект с числовым `building_id` текущего дома и массивом
`cameras`. У каждой камеры нужны положительный числовой `id`, непустой `title`
и исходный `streamURL`; поле `image` необязательно. ID в одном импорте не должны
повторяться. Разрешены HTTPS-ссылки без логина и пароля на `ujin.tech`,
`mysmartflat.ru` и их поддомены, со стандартным HTTPS-портом.

Импорт проверяется целиком до записи. Ссылки хранятся только в приватном локальном
архиве интеграции, не в её опциях. **Не публикуйте резервную копию:** видеоссылки
дают доступ к камерам. Без старой ссылки или восстановленного ответа API
общедомовую камеру восстановить нельзя.

## Проверки разработки

Регрессионные проверки запускаются в окружении Python 3.14:

```bash
pip install -r requirements_test.txt
pytest -q
```

Проверки изолированы от боевого API и не открывают двери.

## Dev-окружение в Docker (без боевого HA)

Локальный HA для разработки форка: код монтируется в контейнер, прод не трогается.

```bash
scripts/dev.sh up        # поднять HA на http://localhost:8124
scripts/dev.sh restart   # перечитать код компонента после правок
scripts/dev.sh logs      # логи (debug по custom_components.domyland включён)
scripts/dev.sh down      # остановить
```

Первый запуск: онбординг HA (создать admin-пользователя), затем один раз
пройти config flow Domyland — та же ссылка авторизации Яндексом и вставка URL
редиректа, что в проде. Токен живёт только в storage dev-инстанса
(`dev/config/`, в .gitignore); в файлы репозитория и в чат его не копировать.

Двери и камеры появятся и здесь — не нажимать открытие на реальном ЖК.
Для правок используется живой монтируемый `custom_components/domyland`
(read-only), поэтому `scripts/dev.sh restart` достаточно, пересборка не нужна.


## Технические детали

- База API: `https://customer-api.domyland.ru`.
- Дом выбирается заголовками `placeId` / `buildingId` (серверного «переключения»
  адреса нет — один токен покрывает все дома).
- Двери и камеры физически привязаны к дому; несколько помещений в одном доме
  (напр. квартира + машиноместо) не создают дублей.
- `iot_class: cloud_polling`, интервал опроса — 5 минут.

## Отказ от ответственности

Проект не аффилирован с Domyland / UJIN / Яндексом. API восстановлен наблюдением за
трафиком собственного аккаунта. Работоспособность зависит от неизменности API
платформы.
